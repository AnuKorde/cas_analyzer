# Format Detection

**Document Version:** 0.1

**Status:** Draft

**Last Updated:** 2026-08-29

## 1. Purpose

This document details stage **IP-05 Detect Format**. CAS Statements can be generated by different depositories (NSDL or CDSL) or RTAs (CAMS, KFintech). Each has a distinct structural layout. This stage determines which parser to invoke.

## 2. Detection Mechanism

The `FormatDetector` inspects the first few pages (or specific header markers) of the extracted text stream.

- **NSDL Detection:** Looks for specific keywords like "National Securities Depository Limited", "NSDL CAS", or NSDL-specific disclaimer text.
- **CDSL Detection:** Looks for "Central Depository Services (India) Limited", "CDSL CAS", etc.

## 3. Supported vs Unsupported

If a format cannot be confidently identified, the pipeline must fail fast (entering the **Rejected** state) rather than attempting to parse the file with the wrong engine. 

```dart
enum CasFormat {
  nsdl,
  cdsl,
  unsupported
}
```

## 4. Evolution

As statement formats change over time, the detector can be expanded to return versioned formats (e.g., `CasFormat.nsdlV2`), allowing multiple parser strategies to coexist.
